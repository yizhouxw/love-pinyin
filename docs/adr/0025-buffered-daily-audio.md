# ADR-0025：天天练编码音频池与复用媒体元素

日期：2026-10-16。状态：采纳。依据：SPEC-008 DAILY-06及iPad实际卡顿反馈。

保留React/FastAPI本地B/S、现有Range服务、摘要校验和no-store权限策略；不引入SSE。当前天天练每段都依赖播放时的网络，daily-audio创建新元素，且缺乏准备/重试状态。采用当天限定的编码Blob池（16MiB/128项、单项4MiB）、2后台+最多1前台下载槽、进行中请求去重及前台优先，完整下载后播放。不会整天解码成PCM，也不存儿童录音、档案或持久缓存。

天天练短音共享一个HTMLAudioElement。首次用户操作同步调用短静音play来获得媒体激活；真实Blob播放才安装进度/完成通知，不能让静音解锁题目或冒充示范。切片结束释放活动Blob URL，保留编码Blob以便复听；切份/退出/后台取消下载并清池，重新操作恢复。课程长MP3继续原生Range，录音回放保持互斥。能力/网络失败明确提示，不判孩子错误。

下载和播放各有超时；仅开始前网络类失败最多重试一次，已出声片段不会自动重头播。采用HTML媒体可保留真实currentTime及原有时间轴，避免新引入Web Audio上下文与iOS录音/后台恢复交互。WebKit建议背靠背媒体复用元素（https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/ ，该文为macOS说明，不是iPad验收）；具体iPad激活与听感仍由用户实测。无新增依赖，不移除儿童语音引导，不建立远程音频通道。
