# SPEC-005：掌握度、复习与家长数据

状态：部分实现（验收未完成）。需求：R-002、R-003、R-007–012、R-018。已有掌握度函数、上海业务日去重、次日复习计划、家长导出和练习数据删除；家长可查看并撤销次设备。schema v2 导出白名单、安全导入预览及服务端确认/原子替换已实现；家长页上传/二次确认 UI 和进度算法完整验收仍未完成。

## 文件和契约

允许 `server/progress/`、`server/storage/` 的进度/导入导出模块、`src/features/progress/`、`src/features/parent/`、对应 schema/测试。服务器是算法唯一执行真源；浏览器只呈现结果，不能另写一套掌握度函数。共享类型和 OpenAPI 应暴露带规则版本的状态、窗口样本数、独立正确数、模式覆盖和复习到期信息。

输入为合法、服务器规范时间的 `Attempt[]`、知识点 `requiredModes`、复习完成事件、当前课范围和注入 `now`。输出为知识点状态/到期计划、下一 6 题计划、家长汇总。requiredModes 仅允许四种客观题模式；算法可防御过滤，但内容校验须拒绝 read-aloud 混入。`read-aloud` 评分摘要独立呈现，不进入客观题掌握窗口或模式覆盖门槛。

## 固定算法 v1

完整依据为 [PRD 第 6 节](../product/PRD.md)。实现时逐条覆盖：

1. 每题实例只有一个首次提交事件；同知识点/题目/北京时间自然日只有第一个事件计入掌握窗口。提示后正确视为未独立正确；重复听标准音不算提示；跳过不计分。
2. 取最新 8 条有效客观题事件。至少 5 条；正确数乘 5 ≥ 事件数乘 4；最近 2 条独立正确；每个 objectiveRequiredMode 至少一条正确，全部满足才已掌握。零事件未开始，其余练习中。客观模式集合为空是内容错误。
3. 首次掌握后次日到期。到期复习 2 道当天未计分的不同题，均独立正确且仍满足掌握规则才通过。阶段 0→1→2→3，对应下次 3/7/14 天，最后维持 14 天；失败重置阶段 0、次日到期。跳过/中断不推进计划。
4. 提前练习不推迟已有到期日。一个知识点每天最多推进一次复习阶段。逾期优先，再按课序/知识点 ID；最多 3 个点 × 2 题。
5. 只在家长当前课及以前范围推荐；调整当前课不删历史。会话开始冻结题单，跨午夜不换题；各题按实际服务端接受日去重，下次日期按完成日。
6. Mac 时间回退超过 5 分钟暂停推进，记录待校时练习但不计算掌握；不自动重写历史时间戳。

服务端必须保存 `masteryRuleVersion`/复习事件版本，导入历史不能因算法升级无说明地改变状态。重新计算应在相同输入和 `now` 下完全一致；派生状态可缓存但事件仍为可重建来源。

## 算法验收表

| 输入                                            | 期望                                  |
| ----------------------------------------------- | ------------------------------------- |
| 0 条有效事件                                    | 未开始；无伪造正确率                  |
| 4/4 正确                                        | 练习中（不足 5 条）                   |
| 5 条中的 4 条正确，最后 2 条正确且覆盖模式      | 已掌握                                |
| 8 条中的 6 条正确                               | 练习中                                |
| 8 条中的 7 条正确，但最后一条错误               | 练习中                                |
| 5 条全对但缺一个 required mode                  | 练习中                                |
| 同题当日练 10 次                                | 至多 1 条进入窗口；次日该题可重新计分 |
| 先提示再答对、先答错再改对                      | 首次独立正确均为 false                |

| 到期复习 1/2、提前练习全对、到期复习只完成 1 题 | 分别重置次日、到期不变、到期不变      |

时间 fixture 至少覆盖北京时间 23:59→00:01、UTC 与北京时间不同日、Mac 时钟回退、迟到/重复响应以及两个设备同日练同题。排序同时间戳用事件 ID；不得依赖数据库无 ORDER BY 的返回顺序。

## 家长页、导入导出与删除

进度展示课/知识点、最近窗口样本量及首次独立正确数、模式覆盖、复习日期和单列的跟读摘要。无需输入儿童姓名、学校和生日。不把规则状态表述成专业诊断或考试等级。

导出 JSON 含 schema/content/rule 版本、UTC 导出时间、匿名 profile、事件/会话/复习/评分摘要及 settings；不含音频、语音特征、配对会话、API 凭据、模型权重。服务器输出固定字段白名单。导出文件最大输入验收为 1 MiB、最多 50,000 条练习事件；超过时清楚拒绝并保持旧数据，不静默截断。随实际容量需求变更需更新 schema 与测试。

导入经过「上传校验 → 预览 → 家长确认替换」；校验 schema、引用、类型/范围、重复 ID、时间、摘要、大小和版本。预览绑定文件 SHA-256、当前数据库 revision 和 5 分钟有效期；确认时任何一项变更则拒绝并重新预览。一次 SQLite 事务替换整个档案，不做隐式合并；故障回滚到旧数据。未知新版 schema 不猜测解析；旧版只能经显式迁移函数。

删除学习记录移除客观题、会话、复习和评分摘要，保留设置/配对/公共资源；重置家庭档案再清除设置并撤销全部设备。两者都需家长管理授权、列清影响和二次确认；取消无变化。已下载的备份无法被服务器远程抹掉，确认页说明。操作完成后其他设备下一次请求应刷新 revision/退出，不继续显示已删除缓存。

## Given / When / Then

- Given 同一事件集以不同数据库读取顺序返回，When 重算进度，Then 结果一致且符合上表。
- Given 家长导入预览后另一台设备新写一条记录，When 确认替换，Then 返回版本冲突，旧数据和新记录均仍存在。
- Given 损坏/超大/未知版本备份，When 导入，Then 全部拒绝、旧数据完全不变。
- Given 有效备份且中途数据库写入失败，When 替换回滚，Then 仍能读取原完整数据。
- Given 删除确认取消，When 返回进度页，Then 记录未改变；确认成功后其他设备也不再取得旧记录。
- Given 家长撤销一台次设备，When 该设备发起下一请求，Then 认证失败并要求重新配对，家长自身设备仍可访问。
- Given 下载备份，When 搜索内容，Then 不包含录音、特征、配对令牌或私有路径。

## 验证与交付

2026-09-26 切片：导出现在带 schema/content/mastery-rule 版本、已完成实例和严格筛选的评分摘要。`POST /api/v1/profiles/import-preview` 流式限制 1 MiB 输入、最多 50,000 次作答，拒绝重复 JSON 属性、未知版本、未知引用、重复 ID、无时区时间和互相矛盾的作答结果；成功只返回短时 opaque token、摘要计数和 SHA-256，不改数据库。`POST /api/v1/profiles/import` 检查家长身份、token、文件摘要、过期时间和 household revision 后，单事务替换会话/实例/作答/跳过/复习/评分摘要并增加 revision；进程内最多缓存 8 个预览、5 分钟过期。会话题目顺序用位置字段保留，恢复后可识别已完成事件；确认写入中途故障的回滚已有回归覆盖。家长管理页面尚未接入导入预览和二次确认操作。

此增量 `npm run verify:all` 通过：14 个隔离 SQLite 服务端用例、10 个 Chromium/WebKit 桌面/平板/手机模拟 E2E 以及前端格式/lint/typecheck/content/unit/build 均通过。Firefox 在本机仍未验证（原因见 STATUS）；此轮 E2E 不覆盖父母导入 UI，因为 UI 尚未接入。

执行 `npm run verify`、`npm run verify:server`、`npm run test:e2e`，用固定时钟和真实事务验证算法、并发、导入回滚与授权。预期全 0；算法边界不依赖真实系统日期。对 PRD 示例做可执行 fixture，但也测试反例与随机输入不变量。

交付版本化进度引擎、家长页、备份恢复/删除、数据 schema 与迁移说明、需求验收证据及 commit。禁止范围：云同步、多儿童账号、自动成绩排行榜、未经验证把跟读分混入掌握度。

低成本模型提示：先把 PRD 规则实现为无 I/O 的服务端函数并用边界 fixture 锁定，再接数据库/UI。不要把五入百分比用于判定，不因题库不足降低掌握门槛，不在导入失败时初始化空档案。
