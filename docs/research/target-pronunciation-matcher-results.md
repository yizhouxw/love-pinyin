## 实装与数据

Qwen VoiceDesign 使用固定的 MLX bf16 转换权重，CosyVoice3 使用固定官方权重与源码。全部模型文件 SHA、上游/转换版本、引擎、Matcha 子模块和许可证保存在 `content/pronunciation-models.json`。CosyVoice 的 LLM/flow 使用 MPS，保留原 CPU HiFT；匹配推理只加载 CPU ONNX。应用依赖未改变，新增依赖锁在两个工具子项目中。

24 个音色家族覆盖四种年龄风格、两种性别风格和三种音色描述。它们是合成风格，不是真人年龄、性别或真实儿童。CosyVoice 使用 Qwen 的虚构参考音，因此两引擎的相同家族及克隆参考始终在同一集合。

| 数据                                        |              数量 |
| ------------------------------------------- | ----------------: |
| 计划生成：32 目标 × 24 家族 × 2 引擎 × 3 次 |             4,608 |
| 通过质量检查的根样本/不同波形 SHA           |     4,074 / 4,074 |
| 隔离 / 生成失败                             |         407 / 127 |
| Qwen / CosyVoice 有效根样本                 |     2,070 / 2,004 |
| 训练 / 校准 / 原留出诊断                    | 3,374 / 330 / 370 |
| 对应家族数                                  |        20 / 2 / 2 |
| 新音色最终复测：有效正例 / 换调或 u、ü 挑战 |          113 / 77 |

原留出家族为年长女性风格；新增复测家族为儿童风格的男声/女声，仍然全部是合成声音。最初用于暴露声调问题的 88 段挑战不作为最终盲测。旧 370 段集也已参与架构问题诊断，因此本报告明确称其“诊断集”，不在修改架构后重新宣传为盲测。

每个训练根样本缓存原音及三个环境变体，合计最多 13,496 份可选训练输入；每轮抽取其一，不算新的根样本。增强包含程序噪声/RIR、增益及保调变速；约 20% 批内样本增加另一个训练音节，参与 CTC 学习。校准/测试不共享训练家族、参考或相同波形。生成文本仅为 TTS 预期标签，时长/能量/削波/有声段检查不能证明所有实际音素、声调均正确。

目标目录有 649 个课程候选/研究挑战，只有明确配置的文本可以送入 TTS，不从字典猜多音字。实际模型只覆盖 32 个完整单音节，其余任务返回 `TARGET_NOT_TRAINED`。分拼、独立声母/韵母、词句、轻声与变调没有借用完整音节模型冒充支持。

## 声调捷径与修正

共享网络采用 64 维 log-Mel + 4 维音高特征，深度可分离 TCN、CTC、声母/韵母分类头及共享声调头；损失为 0.5×CTC + 声母 CE + 韵母 CE + 0.7×声调 CE。网络不输入预期答案，也不使用 ASR、汉字解码或语言模型。

共享声调头在封闭词表表现较好，但新音色换调/u、ü 挑战有 **57/77 被放行**，暴露音节内容与声调标签相关的捷径。仅让微型头看相对音高、用合成 ma 四声训练时，36 段校准的命中仅 38.9%，这条尝试也未作为成功模型。

最终声调头仅输入有声段的 32 点相对 F0 与变化量，不能看到 Mel、音节内容、绝对音高或目标。使用直接信任的既有 PinYinSound 标准音作声调锚：排除全部试验目标的音节组，其余按音节分组为 325 段训练、92 段校准；另有 5 段因数值质量不适用被隔离，不构成对教学标准音的审核。该头有 6,372 参数，标准音校准命中 88.0%，只表示校准结果。

最终新音色挑战放行降至 **5/77（6.5%）**，同时正确音拒判明显上升。该变化支持“独立声调证据能减少捷径”的工程判断，仍不足以证明可靠发音评分。标准音的来源与原许可状态原样保留；这些锚和后面的标准音检查来自同一集合，不能声称独立说话人验证。

## 效果与未通过门禁

所有神经声学对照使用相同架构、种子、160 轮预算和家族划分，检查点只按校准选择。共享主模型选中第 42 轮。单引擎对照的数据量约为双引擎的一半，不能把差异全部归因于引擎多样性。无环境增强对照仍保留多读 CTC 训练。DTW 使用每类一个真实训练样本作模板，没有穷举模板数/参数。

旧 370 段诊断集的完整计数如下；“明确重读”表示模型选中了另一个已支持目标，全部结果均以 TTS 预期标签为参照。

| 模型                           | 匹配 | 明确重读 | 未听清 |
| ------------------------------ | ---: | -------: | -----: |
| Qwen 单引擎                    |  260 |       19 |     91 |
| CosyVoice 单引擎               |  194 |       11 |    165 |
| 双引擎，共享声调头             |  315 |       19 |     36 |
| 双引擎，无环境增强，共享声调头 |  296 |       13 |     61 |
| 最终双引擎 + 独立音高头        |  168 |       21 |    181 |

最终模型的无条件候选首选命中为 85.9%，候选声母/韵母/声调一致率分别为 94.1% / 98.1% / 91.4%；这些是候选分类诊断，不能代替有拒判的最终输出。DTW 的首选命中为 49.7%。

| 最终复测                 | 样本 |      匹配 | 明确重读 | 未听清 |
| ------------------------ | ---: | --------: | -------: | -----: |
| 新合成音色正确音         |  113 |        46 |        3 |     64 |
| 新合成音色换调/u、ü 反例 |   77 | 5（放行） |        1 |     71 |
| 留出标准音记录           |   29 |        14 |        0 |     15 |

32 个目标中 29 个有现成对应标准音，此处没有虚增缺少的记录。标准音是正确读音参考，却与声调训练锚同源；这 29 段没有用于训练或校准，且对应音节组整体排除，仍不等同于陌生真人/儿童验证。

最终模型在 370 段额外音节挑战、20 段纯噪声及静音中没有放行；10/20/0dB 环境测试的全部计数保存在 JSON。低 SNR 的拒判不能写成孩子发音错误。

原计划要求近邻错放行 ≤5%、正确音明确误拒 ≤10%、清晰音拒判 ≤20%。旧诊断集最难反例的错放行为 21/370（5.7%），新换调挑战为 5/77（6.5%）；正确音拒判也显著超过 20%。**因此质量门禁未通过，不能宣称自动发音裁决可用。** “最难反例”按每段音频可能被错接受的候选计数，没有用所有简单反例配对稀释分母。两组新音色及弱标签也不足以给出广泛儿童人群的置信区间。

## CPU 与实际运行验证

Mac Studio、Apple M2 Ultra、24 物理核心、64GiB 内存、arm64。推理固定 `CPUExecutionProvider`、两个 ORT 线程，BLAS 限一个线程。两个 ONNX 顺序运行，总参数 2,397,186，权重合计 2,730,431 字节（约 2.60MiB）。

| 项目                                           |               实测 |
| ---------------------------------------------- | -----------------: |
| 单进程模型加载（不含 Python/NumPy/SciPy 导入） |             48.9ms |
| 29 段标准音，暖机后端到端 p95                  |             13.0ms |
| 四秒重复真人语音，端到端 p95 / 实时率          |    54.0ms / 0.0135 |
| 进程峰值 RSS / 峰值增量                        | 181.2MiB / 87.1MiB |

计时覆盖 WAV 解码、特征、两个模型和全部候选比较，从 Python 字节输入到结果；没有包括以后应用层的采音、编码、HTTP 或 LAN。四秒重复语音用来测长度压力及多读拒判，不算新的正确发音或儿童数据。29 个四秒重复样本均未放行。未测与家庭应用并行的负载。

16 项底层测试已实际运行，其中三项加载真实本地权重，检查纯 CPU、阻断 Python 网络连接时推理、取消后不返回迟到结论、最小安装与损坏声调头不降级。独立 `.runtime` 环境确认没有 Torch、MLX、TTS、Whisper 或 Librosa。CI 只跑不需私有权重的测试，三项产物测试在没有显式路径时跳过，不冒充模型验证。

`npm run verify:all` 和 `npm run validate:release` 通过，表示既有应用工程/内容门禁未受影响，不能替代本模型的效果门禁。没有声称完成真实移动设备、家庭 LAN 或儿童验收。

## 本地使用与下一步

```sh
./tools/pinyin-matcher/run.sh info --model models/pinyin-matcher
./tools/pinyin-matcher/run.sh match --model models/pinyin-matcher \
  --target pm-ma1 --wav /absolute/path/reading.wav
```

输入为 16kHz、单声道 PCM16 WAV，返回 `matched/retry/uncertain/unavailable`，不返回儿童分数。当前始终带 `experimental=true`、`toneAssessed=false`；无可靠证据时拒判。运行不下载模型、不写入录音、不调用通用 ASR。

后续优先改进生成标签质量和跨音节四声对立覆盖，验证受控读音/承载句方式，再做冻结阈值的独立真实语音实验。无需等待儿童数据才能继续合成研发，但不能用增加噪声或样本数代替正确标签、声调信息与真实域验证。本次保留这些明确失败门禁，不将实验能力接入儿童自动成绩。
