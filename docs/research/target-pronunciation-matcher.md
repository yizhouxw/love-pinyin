# 目标拼音匹配器技术方案

日期：2026-10-25。关联 [SPEC-018](../specs/SPEC-018-target-pronunciation-matcher.md)、[ADR-0034](../adr/0034-target-pronunciation-matcher.md)。本文保留最初的设计与预算；已实施的版本、实测结果及未通过门禁以[实验记录](target-pronunciation-matcher-results.md)为准，不能把计划数字当作实测。

## 1. 任务定义

给定课程目标和标准读音，判断孩子这一段声音是否与该目标相符。首轮针对完整单音节，分别研究声母、韵母和四声；结果有匹配、建议再读、未听清和服务不可用四种。系统不需要把任意讲话转成汉字，也不需要开放词汇解码器或语言模型。

“识别出同一音节”与“发音准确度”有区别。第一阶段能证明的只是有限目标和近邻之间的区分；清晰读出另一个音节属于可构造的反例，细微口型/送气/构音偏差是否被识别，需真实错误样本验证。数值置信度留作内部校准，不直接包装成百分制能力分数。

任务必须显式区分完整音节、单独声母呼读、单独韵母及分拼后合读。比如整读 bā 与 b—ā—bā 不是同一条音素序列；有意允许分拼的题目登记有限的可接受序列，不能推理时任意删除多读音节。连读、轻声、三声变调及“一/不”变调另做词句阶段，不用孤立音节四声规则评判全部句子。

实施使用独立的 Qwen VoiceDesign MLX 环境和 CosyVoice 环境，不改变应用依赖。转换权重来自 `mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-bf16`，固定修订及全部文件摘要见 content/pronunciation-models.json；官方原模型来源同时保留。Python 3.12、推理/训练/生成依赖均由工具子项目 uv.lock 冻结。本机实装与许可证清单见[工具文档](../engineering/pronunciation-matcher.md)。

音色库先设计 24 个家族：四种年龄风格（低龄、较大儿童、成年、年长）× 两种性别风格 × 三种音色描述。元数据记为 `styleAgeBand/styleGender`，不记为真人年龄/性别。Qwen 的相同描述未必生成稳定身份，按描述家族保守分组；CosyVoice 可用 Qwen 生成的非真人参考音保持音色，但其参考音和全部后代必须保留在同一数据集合。两种合成引擎不能因此算成两个独立说话人。

## 3. 标签及生成质量

课程清单是范围来源，不能由 TTS 或组件自由发明目标。当前内容有 79 个历史 readingTargets、785 条每日材料，其中显式 syllables 去重为 654 个带调/呼读字符串；这些数字是目录统计，不是已完成的数据集。以正式编译后的目标清单计实际数量，不把全部拼音理论组合都当作合法音节。

已实现 `content/pronunciation-targets.json`，集中登记规范 NFC 拼音、发音形式、音素序列、声调、近邻、允许读法和现有标准音 ID。ü、j/q/x/y 后的拼写、省写和不同 i 的实际发音在这里统一处理；不能仅把拉丁字母逐字符当音素。单独声母教学呼读与音节内真实辅音分别登记。

Qwen 的输入优先选读音单一的汉字/短承载句；直接输入拉丁拼音不保证得到预期读音。CosyVoice 的拼音控制先作最小验证，不能把其官方能力说明推断为所有孤立声母/韵母都能准确生成。承载句截取必须保留完整辅音起始和韵尾；截取后有明显上下文/变调影响的样本不用于孤立目标标签。

每个根样本记录 `targetId/actualPhones/actualTone/generatorRevision/voiceFamilyId/referenceRootId/text/seed/sha256`。TTS 文本只给出预期标签，不能直接证明实际音频正确；检查空音、截断、多读、时长、音素/音高异常，并对易混淆目标及每种生成条件作开发者听辨抽查。抽查不确定的生成条件整体隔离，不能给其全部后代自动贴正确标签。辅助 ASR/对齐器只能用于找异常，不能替代真实听辨，也不参与产品裁决。此为训练数据质量检查，不增加教材标准音审音流程或教师审核角色。

## 4. 正例、近邻与环境增强

同一个清晰的 pā，针对 pā 是正例，针对 bā 是近邻反例。优先生成 b/p、d/t、g/k、n/l、z/zh、c/ch、s/sh、u/ü、前后鼻音及同音节不同声调等最小对立。音节插入、遗漏、多读与音量不足分别保留标签；合法音节的替换仍不能代表全部真实儿童构音错误。

正负配对在两个引擎、音色、音量、时长和设备条件中保持均衡，避免“某模型声音等于错误”。不能对全部正例使用干净声音、对全部反例使用加噪声音。

环境增强在训练时按固定种子在线产生，默认保留部分干净样本：

| 增强                 | 初始范围                                     | 标签处理                                                      |
| -------------------- | -------------------------------------------- | ------------------------------------------------------------- |
| 背景噪声             | 语音区域 SNR 10/20/30dB，及另列的低 SNR 挑战 | 保持实际音素；听不清标质量不确定，不标发音错误                |
| 房间混响             | 程序生成 RIR，初始 RT60 0.15～0.6 秒         | 保持实际音素，强混响作为拒判挑战                              |
| 增益、距离及设备响应 | 增益 ±6dB，有限带宽、首尾静音和轻微编码失真  | 不以音量、设备类别预测发音正误                                |
| 语速                 | 保持音高的 0.85～1.15 倍时间伸缩             | 防截断；检查伸缩伪影，失真样本退出发音标签                    |
| 音色变化             | 温和的整体音高/声道长度变化，作为单独消融    | 保留原声调轮廓，仅用于通过质量检查的样本；不随意拉平或扭曲 F0 |

不采用简单重采样制造“儿童发音”：它同时改变时长、F0 和共振峰，不能代表儿童构音。改变整个 F0 高度不自动产生另一声调；故意改变声调必须给出明确的新标签并验证。噪声优先采用程序生成或已登记许可的非隐私资产，首轮不需要下载背景人声数据集。

先按 `voiceFamilyId + referenceRootId` 及全部生成/增强谱系分配训练、校准和测试，再生成增强；关联分组取连通分量，不能仅对 WAV 随机 8:1:1 分割。开发/测试保持原始根样本计数，置信区间按说话人/音色家族分组。另做未见生成器、未见音节组合、未见噪声/RIR 和真实录音评估。

## 5. 确定的匹配架构

```text
16kHz PCM + 白名单 targetId
        ↓
时长/静音/削波/信噪与语音质量检查
        ↓
64维 log-Mel（25ms窗、10ms步长）    F0/有声概率/相对音高及变化率
        ↓                             ↓
小型深度可分离卷积 + 时序卷积编码器（不输入目标答案）
        ↓                             ↓
帧级音素后验 + CTC                声调与可靠性分支
        └──────────────┬──────────────┘
                 目标/近邻/增删音比较
                       ↓
             冻结阈值与拒判 → matched/retry/uncertain
```

初始规模 2～5M 参数，使用帧级表示保留辅音起始、送气和韵尾证据；第一版不选需要大模型前向推理的通用语音编码器。本轮共享编码器使用 0.5×CTC + 声母 CE + 韵母 CE + 0.7×声调 CE，未另行实现对比学习损失；各分类头共同训练。最终声调预测另由只看相对 F0 的微型 ONNX 提供：纯合成 ma 四声试验不足后，使用标准音的其他音节作为声调锚，细节及失败结果见实验记录。对不完整/非语音输入训练质量拒判；不能把实际错音的全部证据推给质量分支逃避错误检测。

推理时先计算目标无关的音素后验，再用 CTC 前向算法比较目标及近邻的完整序列概率；校准不同长度的偏差，同时检查额外语音、音素缺失和开放音素解码证据。以目标绝对证据、最近反例间隔和质量置信共同决定结论。只有“比几个近邻更像目标”不足以通过：无关讲话也可能在有限候选中排第一。

声调分支结合谱特征和有声段的相对 F0 轨迹；不比较男性成人和儿童的绝对音高，不按每个短音节自身 min-max 归一化抹掉一声/三声差异。音高分析初始覆盖约 60～900Hz，并检测倍频/半频及无声段；范围和拒判阈值在真实样本上调整。单音节基准难以恢复说话人的完整音域，因此声调不可靠时允许单独拒判，不让有限模板距离给出虚假确定性。

标准音用于示范和开发对照；模板距离（log-Mel/MFCC + 带约束 DTW）保留为可复现基线，神经模型必须在未见音色、近邻及真实录音上优于它才值得增加复杂度。不直接用原始波形、单一整体 embedding 或波形余弦相似度裁决。

这些是本项目的架构选择，不能声称论文已证明该小模型在一年级儿童上有效。参考：[轻量卷积语音任务研究](https://arxiv.org/abs/2106.04140)、[普通话音系特征与声调分开建模](https://arxiv.org/abs/2606.22022)、[音高特征用于普通话发音检测](https://arxiv.org/abs/2406.04595)。后两类研究的较大网络及成人学习者结果不直接移植为本项目性能数字。

## 6. CPU 部署与性能预算

产品只运行导出的声学匹配器，TTS 和训练任务不在实时链路中。FP32 ONNX 先建立正确性/延迟基线，再对卷积分支做静态 INT8/QDQ 校准；F0、阈值与必要输出层可保留 FP32。量化后重新验证近邻、声调及拒判表现，不因文件更小就默认通过。ONNX Runtime 官方建议卷积模型优先静态量化，并要求处理量化精度损失，见[官方量化文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)。

显式 `CPUExecutionProvider`，固定两个推理线程、单任务推理、有限请求体与超时；忙时返回不可用，不排无限队列。目标清单、标准音、模型及阈值按版本/摘要一同冻结。模型只经显式安装准备下载；推理不访问外网，不自动更新。

| 项目                     | 待验证目标                                          |
| ------------------------ | --------------------------------------------------- |
| INT8 权重                | ≤10MiB，另记配置/运行库占用                         |
| 模型进程增量内存         | ≤200MiB                                             |
| 暖机后四秒以内录音实时率 | ≤0.1，另报不同音频长度的分布                        |
| 停止录音到结果 p95       | ≤500ms；含解码、特征、推理和本地请求，两个 CPU 线程 |
| 冷启动                   | 单独记录，不能只报暖机结果                          |
| 真实负载                 | 模型匹配与现有声音播放/家庭服务同时运行时复测       |

这组参数预算使 CPU 路线合理，但不是速度保证。用目标 Mac 的真实人声/标准音、固定并发和全链路计时验证；不以合成正弦推理或上游 TTS 的首包延迟作证据。批量合成和训练可使用本地 GPU/Metal，CPU 要求仅约束产品匹配算法。

## 7. 数据量、消融与验收

第一实验采用 32 个目标、两引擎、16 个音色家族、每条件三个根样本：计划约 3,072 段独立生成片段。实际有缺音/标签异常时报告有效数量；加三个增强版本为约 12,288 次输入曝光，不写成一万多个独立说话样本。先选覆盖四声及上述近邻的目标，不追求一次做完全部课程。

全量预算按当前 654 个候选字符串估算：654 × 2 × 24 × 3 = 94,176 个根样本；平均两秒约 52.3 小时音频，16kHz PCM16 约 6.0GB，不含原生成格式、检查产物和模型。该预算只有生成耗时/质量小试通过后才展开；增强在线执行，避免将每份噪声变体全量存盘。

按以下顺序执行，前面的合成研发不等待真实儿童数据：

1. **MATCH-02A 数据小试**：验证两模型本机安装、实际中文/拼音读音、24 类音色设计的可控程度和单位生成耗时；先完成少量目标，再扩至 32 目标。冻结数据版本、生成参数与排除样本。
2. **MATCH-02B 划分与反例**：自动查父子样本/参考音泄漏，覆盖正确/近邻/增删音/噪声/静音；证明噪声和引擎没有成为正负标签捷径。
3. **MATCH-03A 模型比较**：比较 DTW 基线、单引擎、双引擎、无增强、仅环境增强、加入声调分支，锁定开发集后只在冻结测试集报告。合成近邻错放行目标 ≤5%，正确音明确误拒目标 ≤10%，清晰语音拒判目标 ≤20%；拒判不能悄悄从统计中消失。
4. **MATCH-03B 真实域验证**：用独立的真实成人读音首先检查合成到真人的差距；再由自愿参与的目标年龄儿童作家庭小试。报告不同人、设备、声母/韵母/声调与环境的错放行、误拒、拒判及分组置信区间，单列普通家庭样本和合成测试。
5. **MATCH-03C CPU 与安全失败**：实际导出/量化、两个 CPU 线程计时；覆盖静音、过短、截断、削波、不同采样率、超长、忙、缺模型和停止/迟到响应。返回不可用/不确定不能产生儿童错误成绩。
6. **SHOP-01～03 游戏接入**：在原创商店场景中接录音、标准音示范、真实反馈、六件一轮、家庭时长和退出恢复。模型未覆盖的目标不自动作发音裁决；家长放行单独标记。完成工程/内容发布检查、实际浏览器声音及真实设备/家庭 LAN 试用。

真实录音只在家庭 Mac 范围处理。日常游戏不保存录音；研究数据若需要保留或用于训练，另走显式自愿研究入口，训练目录不进 Git，不能悄悄从游戏收集。真实儿童样本不是开始合成训练的前置要求；但没有这类独立验证，就不宣称儿童自动准确度已成立。[儿童语音 GOP 研究](https://www.isca-archive.org/interspeech_2023/cao23_interspeech.html)说明儿童语音评估与成人存在不同分布，因此不能只靠“听起来年轻”的合成音色验证。

既有 `research/assessment/benchmark.py` 仍是历史研究评估器，其 schema 只接受真人 cohort，部分门槛来自旧 SPEC；不能把 synthetic 记录冒填为儿童或直接据此宣布新方案验收。新实验需要独立合成 manifest 和真实域评估入口；研发进度不受旧评估器一律返回 continue-research 的历史设计阻塞。

本模型没有活体鉴别能力：麦克风录到标准音回放时，声学上可能就是标准读音。产品先停止全部示范再开放麦克风并留短消声间隔，降低自播声音串入；不能因此声称能识别所有外部扬声器回放。

## 8. 本次交付范围

已实现独立底层工具链、实际合成/训练/校准/量化、CPU 推理和本地最小模型包。首轮效果没有达到可靠自动裁决门槛，因此没有盲目扩到约九万条全量数据，也没有接入游戏。完整数值、能力边界及后续门禁见[实验记录](target-pronunciation-matcher-results.md)。
