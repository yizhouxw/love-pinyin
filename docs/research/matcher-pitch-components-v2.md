# SwiftF0 contour v2：弱且不连通的有声片段

V4 的权重、特征版本、报告和阈值保留为历史。以下是新候选特征，不代表通过新的独立质量验收。V4 已公开样本只作诊断，不能再次称为盲测。内容分支和 CTC 始终使用完整原始波形。

## 在训练前固定的算法

- SwiftF0 0.3.0 的模型、16 ms hop、46.875–1000 Hz 范围和逐帧有声阈值 0.5 不变。
- 将有声帧按时间分成组件；相邻有声帧之间至少六个无声 hop（96 ms）才分开。
- 按有声帧 RMS 平方和选主要组件，只作音高特征的参考。一个其他组件必须同时满足三条件才可排除：至多六个有声 hop（96 ms）、中位置信小于 0.8、中位 RMS 小于主要组件的 15%。这些常量是机制保护，不能按已失败的测试集扫描或选择。
- 相连的下降尾巴、短喉化间隙和三声谷底不因低音高、低能量或短时低置信而被该规则删除。音高高低和目标答案不参与筛选。
- 不符合上述三条件的组件保留；不把有意义的第二音节在内容分支里删除。保留组件之间的置信/有声 mask 仍进入 32×4 特征。
- 只有去掉符合全部条件的弱组件后才取首尾、插值并计算相对 log2 F0、导数、置信及有声 mask。少于六个保留有声帧则拒绝提供音高证据。
- 新版本 `relative-swift-f0-0.3.0-components32-v2`，旧 `relative-swift-f0-0.3.0-contour32-v1` 的计算逐字保留；运行时由模型 metadata 显式选择，组装器不能静默更换。

## 训练与选择边界

仅使用原标准音 325 个 train / 92 个 calibration，沿用原 10468 参数 MLP、固定随机种子、300 epochs、逐声调平衡和仅 calibration loss 选择 checkpoint。绝不引入 V4 测试的标签或波形训练。比较完整 92 个 calibration（提取失败计错）的 top-1；正确数相同时，才比较 NLL。只有 calibration 表现更好才推荐组装新版本。该比较是开发集选择，不建立儿童或独立人群准确度。

单测包含断开的短弱尾排除、连接的低音下降尾/谷底保留、强的第二组件保留、旧版本结果不变、metadata 版本验证，以及可选的授权标准语音回归。构造信号仅验证边界契约，不作为拼音准确度证据。

## 实际比较与决定

原 325 train 和 92 calibration 全部可提取。325 个 train 的特征逐值不变，300 epochs 后选出的第 56 epoch 权重也与旧头完全相同：`a823601bae50b1506325581d6e0d2cf467c53811552cb1c609de44f593cb6759`。

完整 92 个 calibration 两者都正确 91 个、提取失败 0 个；不平滑的平均 NLL 从旧版 `0.0507879134` 变为新版 `0.0508398968`，新版稍差。仅 `daily-i4` 的特征改变：删除一个断开的两帧弱组件后仍判四声，但正确声调概率从 `0.97864` 变为 `0.97397`。带 label smoothing 的训练选择 loss 微降不能当作真实 NLL 改善。

依照事先声明的“正确数，然后 NLL”选择规则，**保留 v1**。v2 代码与私有候选保留，不用于 V5 模型组装。实际比较记录为 `private/matcher-pitch-components-v2-standard/comparison.json`；新头及训练过程在同目录，旧目录和 V4 报告未覆盖。两种版本均已用真实 ONNX 做组装/加载验证，组装时必须显式传入对应 `--feature-version`，并校验 `pitch.json` 的特征版本与模型 SHA。

可公开核对的计数、NLL、源清单与权重/代码 SHA 见[实验摘要 JSON](matcher-pitch-components-v2-results.json)。该文件不含音频或大模型。
